# Toolkit verification: 2026-10-05

Scope: the reusable portal toolkit, not a tracked application. Environment: Windows, Python 3.12.14, local virtual environment, in-app Chromium browser. No macOS/Linux execution or independent coding-assistant onboarding trial was performed.

## Commands and results

Commands were run from the portal root, using its local Python after setup:

~~~powershell
python scripts/portal.py setup
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe scripts/portal.py check
.venv/Scripts/python.exe scripts/portal.py build
.venv/Scripts/python.exe scripts/portal.py serve --port 8010
~~~

- Setup: succeeded; dependencies installed into this portal's .venv, not globally.
- Unit tests: 19 methods passed, no skips. Positive and negative cases cover metadata, rendering, navigation, links, private paths, read-only checks, local environment checks, port validation, and subprocess behavior. Several methods use multiple subcases.
- First unit-test run: 18 passed, one assertion failed because a test expected POSIX path separators on Windows. The expectation was changed to use pathlib; the full rerun passed. This was a test portability correction, not an ignored failure.
- Content check: passed for the starter documents and configuration.
- Strict build: passed without reported build warnings.
- Serve: content checks passed; loopback HTTP access succeeded on port 8010. This is a foreground development server, not a persistent service or hosted deployment.

## Publication hygiene and limits

Git ignore checks exclude .venv, site, .portal/user-preferences.local.md, and .env. A limited text-pattern check found no copied personal machine paths or graduation-project/circuit content in the reusable source documents, scripts, tests, and templates. This is not a comprehensive security audit. Review new project material before publishing it.

Direct dependencies are pinned; transitive dependencies are not locked. Initial setup needs network access. Mermaid rendering may need an external asset; offline diagrams are not guaranteed. The content checker does not prove remote links, anchors, all Markdown dialects, or application correctness.

The toolkit's own verification is kept here so the blank starter does not pretend a user's project has already been implemented or tested. No real preferences, transcripts, or application history are bundled.
